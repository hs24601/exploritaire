Historical experiment: production now uses [the playable transparent screen rail](./world-combat-rail.md). The diegetic foundation/tableau placement below is retained as design history and is not instantiated in the game.

The page-1111/portals woods now contains two real scene surfaces. From the existing behind-Hero opening, her foundation rests on a sampled floor patch behind her feet; Khadroot's foundation faces the camera behind and to the right of the enemy. The card layout follows the supplied landscape foundation references, reusing Hero's existing emoji painting. No new character art was generated.

The nearer team receives the floor foundation; the farther team receives the billboard. A one-metre depth advantage is required to exchange these roles, avoiding toggling around a side-on orbit. Both use ordinary perspective and scene depth, so foreground actors/trees can occlude them. The floor's 12×8 patch samples actual supported terrain at each vertex, with a small separation and polygon offset to prevent ground z-fighting. Foundations are excluded from navigation obstacles and point-to-click picking.

Readability refinement: the latest reference sets a maximum 35° obliquity (about 82% face-on projected area before perspective). Floor prints retain their ground contact edge but prop toward the viewer when needed; a smooth footprint reduction prevents the raised face from hiding Hero. Iterative correction measures the actual transformed face center, and terrain-clearance checks keep the print above the ground. Far billboards use the same actual-eye-ray cap for extreme off-axis views; ordinary camera-parallel poses remain unchanged. Far offsets increased 20% to 3.6 m right and 1.98 m high. Seven layout/state tests cover these refinements, including low cameras and off-axis billboards; the opening/reverse/live-state scene check passed after the footprint correction. This supersedes an unconditional floor-flat requirement when it would make text unreadable.

Canvas textures repaint only when values or the portrait change. This first placement pass has no foundation click/drop interaction. It preserves the existing tableau layout and encounter dialog. Hero is the current party anchor and the existing Khadroot is the enemy anchor; a future multi-actor formation pass can provide additional world anchors.

Waiting cards derive from the canonical actor roster, initial enemy ranks and authored scenario-001 HP. They do not instantiate a battle/deal or advance clocks. Encounter changes and retreat snapshots supply actual rank, HP, AP, status and stagger values thereafter. Victory hides the defeated encounter's panels. No extra lights, captures, frame-by-frame texture rasterization or render loops are added to production.

## Six midfield columns

The next layout pass adds six rank-card stacks: three to either side of a clear central corridor. Their bases sit 48% of the distance from the near actor toward the far actor, with lateral offsets −4.25, −3, −1.75, 1.75, 3 and 4.25 metres. Each card keeps its 63:88 aspect, with a modest fan exposing covered ranks. All cards copy a basis extracted from the corrected near foundation geometry, giving the same yaw, tilt and roll instead of six independent facing corrections. Terrain determines each column's base; normal depth allows actors and vegetation to occlude the cards.

The waiting layout reads the canonical authored training deal without constructing an encounter or advancing timers. Once combat is opened, the woods-specific initial state adapts to six logical columns, moving every extra-column card into stock. Withdraw uses the configured tableau width and retains overflow cards in stock, preventing a seventh column from returning on redeal. Other seven-column scenarios keep their existing width. Each mesh retains source column, depth, card ID/rank and exposed status; values repaint/update when the actual battle state changes.

One shared 14-cell canvas atlas (thirteen ranks plus empty slot) and one shared depth-tested material serve the six stacks. The default waiting arrangement contains 24 meshes. These are code-rendered rank-card UI, using existing card ranks/labels, without generated illustration or added lamps/capture passes. Cards and empty slots do not intercept navigation. Interaction still belongs to the existing combat interface; this is an in-world placement pass.
