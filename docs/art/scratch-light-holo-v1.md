# Scratch-style holocard revision

The original Scratch prompt trail shows two distinct operations: the v2 paint-method change to large diluted wet washes and lifted apricot/ivory/slate colors, followed by v3's removal of enemies while keeping that paint method. `art.md` now contains a reusable production prompt, reference roles, exclusions, alpha rules and visual acceptance criteria reconstructed from that evidence.

Built-in ImageGen produced Hero's `hero-watercolor-v6-organic-bobtail.png`, four registered Bite paintings under `runtime/ui/holocards/hero-bite/v2/`, and the softer four-plane Fast Swipes set under `runtime/ui/holocards/mochi-fast-swipes/v3/`. Every selected image is copied byte-identically into the corresponding sources directory. Exact prompts and references: [scratch-light-holo-v1.json](./scratch-light-holo-v1.json). Earlier versions remain historical. Hero's holoart no longer mounts the old flame motif overlay; this does not change world sprite rigs.

Bite is a simulated lenticular angle flip, not a timed animation or an optical diffraction simulation. It reads the existing calibrated pointer/gyro spring's lateral axis. Absolute lateral position 0–1 selects closed, slightly parted, half-open and open paintings, with brief transition bands at .20–.25, .47–.52 and .74–.79. Looking straight at the card shows closed jaws; either steep side shows open jaws. Returning toward the center reverses the sequence. Vertical tilt does not select frames. All four subject paintings share their crop and parallax plane; the forest remains independent. Labels and gameplay never depend on the selected picture. Reduced motion and low/off effects hold the closed painting; HP loss still temporarily uses the existing flinch artwork.

Foundation clicks now open the Keru portrait next to a selectable ability gallery, recommending Bite for Hero and Fast Swipes for Mochi. The signature previews use current encounter rules and counters; other catalogue entries show their authored costs and descriptions without implying that inspection casts or equips them. Combat pauses for the inspector, while jumbo-card motion uses the browser UI clock so tilt remains responsive. On narrow screens the content scrolls within the dialog.

Verification: `tools/fast-swipes-layered-jumbo-check.cjs` checks the ability galleries, mobile flow, separate swipe transforms and reduced motion. `tools/bite-lenticular-check.cjs` checks all four jaw states, symmetric steep angles, the actual pointer spring while combat is paused, reversal, flame-overlay removal and closed reduced-motion fallback. `tools/bite-reaction-gyro-check.cjs` covers flinch refresh/restore, healing ignored and sensor-event-driven tilt without changing hitboxes. `tools/prime-transfer-check.cjs` retains foundation drag regression coverage. These browser checks do not certify a physical phone's sensor permission or optical holography.
